# bi

## Working rules

1. Before implementing, document the spec in `docs/specs/*`.
2. Write code that allows different frontends to be built in the future, so the
   core and its logic stay easily embeddable.
3. Always suggest the best architectural choice first, no matter the cost. Think
   about the future.
4. When the work is done, commit and push it. Straight to `master` — never a
   feature branch.
5. Git commits should be simple, rather short. Never add Co-Authored-By messages or any other Claude related.
