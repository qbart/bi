# Debugger (DAP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A built-in debugger — gutter breakpoints, launch/attach-by-pid, stepping, and panes for variables/stack/console/watches — driven by one DAP client that mirrors `src/lsp/`.

**Architecture:** `src/dap/` is a sans-IO core (types, rpc, client state machine, registry with an Effect enum) with I/O only at the transport edge, exactly like `src/lsp/`. Reader threads decode frames onto an `Inbox` and call a waker; a new `Wake::Dap` arm drains it, and everything becomes editor state inside `Editor::settle`. A real `Mode::Debug` and a `DebugCmd` enum carry the editor-facing surface. Four new `ContentKind` variants render the panes like Tree/Results already do.

**Tech Stack:** Rust, `serde`/`serde_json`, `std::process`/`std::thread` (no async runtime — the LSP module's thread-trio pattern), `toml` config.

**Spec:** `docs/specs/debug.md`

## Global Constraints

- **Mirror `src/lsp/` layer for layer.** Module names, trait seams (`Spawn`/`Transport`), the `Inbox`/waker/`Wake` handshake, and the `set_*_spawner`/`set_*_waker` lib boundary all follow LSP's shapes verbatim. Reuse, do not re-derive.
- **Editor is the single owner of truth.** Reader threads only decode-and-deliver; all interpretation happens in `settle()`. No event bus, no closures held across the boundary — typed intents (`Intent`) and typed effects (`Effect`) only.
- **DAP framing is identical to LSP.** Same `Content-Length` frames. Reuse `lsp::rpc::{encode, read_frame}` for framing; DAP only differs in the envelope (`seq`/`type`/`request_seq`/`success`) and in being event-driven.
- **The launch/attach body is never modelled.** It is adapter-specific JSON, passed through opaquely as `serde_json::Value`.
- **Adapter processes never spawn in tests or headless embeddings.** A `fake` spawner (mirroring `lsp::transport::fake`) backs every test.
- **Comment style matches the codebase:** dense, literate, explaining *why* not *what*. Every public item documented in the surrounding house style.
- **TDD throughout.** Every task is failing-test-first. Run `cargo test` (workspace) and `cargo clippy --all-targets` before each commit; both must be clean.
- **`ServerId`-style identity:** DAP sessions get a `SessionId(pub u32)`, handed out monotonically, never reused — same reason as `ServerId`/`BufferId`.
