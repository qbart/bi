# Curve Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `:set editor curve` on a point list in code draws it as a hermite curve beside the source, and `hjkl`/`HL`/`a`/`i`/`x` on the plot rewrite the numbers in place.

**Architecture:** A pure `src/curve.rs` (bracket scanner, layout, token rewrite, hermite eval, rasteriser) with no editor in it. The editor grows a `Tool` enum over the existing normal-map tool and a new `CurveTool` whose truth is the source buffer: every key edits the buffer as one undo step, `sync_tools` sees the buffer's edit counter move, re-finds the literal, re-reads the curve, rebuilds the form and re-renders the plot into an ordinary `Img`.

**Tech Stack:** Rust, the existing `Form`, `Img`, `Buffer` (ropey), `Window`/`Content` machinery. No new crates.

**Spec:** `docs/specs/curve.md` (and the `Tab` amendment in `docs/specs/form.md`).

## Global Constraints

- Commit messages: short, plain, no `Co-Authored-By`, no Claude mention (CLAUDE.md).
- Every commit goes straight to `master` and is pushed.

- Messages copied verbatim from the spec: `no curve under the cursor`, `curve lost`, `a curve keeps two points`, `curve point=2`.
- Default layout `x,y,out,in,locked`; `_` skips a field.
- Number rewrite keeps suffix and at least the token's decimals, never fewer than the step needs.
- Tests: `cargo test` must stay green; run `cargo test curve` for the fast loop.

```rust
//! The curve editor's pure half: a point list in code, read and rewritten
//! by token. See `docs/specs/curve.md`.

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Field { X, Y, Out, In, Locked, Skip }

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Layout(pub Vec<Field>);

impl Default for Layout {
    fn default() -> Self { Layout(vec![Field::X, Field::Y, Field::Out, Field::In, Field::Locked]) }
}

impl Layout {
    pub fn parse(s: &str) -> Result<Layout, String> {
        let mut fields = Vec::new();
        for part in s.split(',') {
            fields.push(match part.trim() {
                "x" => Field::X, "y" => Field::Y, "out" => Field::Out, "in" => Field::In,
                "locked" => Field::Locked, "_" => Field::Skip,
                other => return Err(format!("not a field: {other} (want x, y, out, in, locked or _)")),
            });
        }
        if !fields.contains(&Field::X) || !fields.contains(&Field::Y) {
            return Err("a layout needs x and y".into());
        }
        Ok(Layout(fields))
    }
    pub fn text(&self) -> String { /* join names with "," */ }
    pub fn index_of(&self, f: Field) -> Option<usize> { self.0.iter().position(|&g| g == f) }
}
```

Tokenising: walk bytes; a **group** opens at `{`, `[`, `(` and closes at the matching `}`, `]`, `)`; string literals (`"…"`, `'…'`) and `//`/`#` line comments are skipped so brackets in them do not count. A **token** is a number (`[+-]?digits[.digits][e[+-]digits]` followed by glued `[A-Za-z_]*`) or the words `true`/`false`; a `-` only starts a number when the previous non-space byte is not a digit/identifier char (so `1-2` is not `1` and `-2`; nobody writes that in a point list, but the rule is cheap). Identifiers are consumed and dropped (`in_`, `Point`, `x`), except `true`/`false`.

Algorithm for `find`:
1. Build a tree of groups over the whole text: `struct Group { open, close, children: Vec<Group>, tokens: Vec<Token> }` where `tokens` are the direct number/bool tokens of the group (not in a child) and children the nested groups. One recursive descent pass; an unclosed group closes at end of text.
2. `qualifies(g)`: `g.children.len() >= 1` and every child yields at least two numbers when flattened (child's own tokens plus its descendants' tokens, in text order) and `g.tokens` (direct numbers) is empty. Take the innermost group *containing the cursor* (open <= cursor <= close) that qualifies, walking outward.
3. Build `Literal { open, close, points }` where each `PointSpan { start: child.open, end: child.close + 1, tokens: flattened }`.

`read`: for each point, for each `(i, field)` in layout, `tokens.get(i)` → parse (`f32` after stripping the glued suffix; `true`/`1` → locked) into the field; missing → default.
